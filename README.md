# Muxer — 视频字幕封装工具

**简体中文** · [繁體中文](README.zh-TW.md) · [English](README.en.md)

**Muxer** 是一款基于 [Wails v2](https://wails.io/) 的 Windows 桌面应用，用于把外挂字幕与视频封装在一起（软封或硬压），并附带一套视频与字幕处理工具链。界面为中文，面向影视字幕组、个人收藏整理等本地批量处理场景。

所有媒体处理都由本机 **FFmpeg** 完成，视频不会上传到任何服务器；只有语音转字幕、AI 字幕修复等功能会调用你自己配置的云端 API。

仓库：<https://github.com/MuxerGUI/Muxer> · 协议：[MIT](LICENSE)

## 功能特性

### 封装（核心）

- **软封（内嵌字幕轨）**：视频流直接复制，字幕作为独立轨道写入，零画质损失
- **硬压（烧录进画面）**：H.264 / H.265 / AV1，支持 CPU 与 GPU（NVENC / AMF / QSV）。硬件编码不可用时自动改用 CPU 重试一次
- **关键帧间隔上限**：硬压输出按帧率设置约 2 秒的关键帧间隔，保证拖动定位精度与 HLS 切片可对齐
- **同时产出在线版**（硬压可选）：一条 FFmpeg 命令里同时输出母版与一路 1080p 小体积 MP4，共用一次解码与一次字幕烧录。在线版与母版同目录、同主文件名加 `.在线版.mp4` 后缀，立体声 AAC、`+faststart`、约 2 秒关键帧；码率留空时跟随片源（上限 3000 kbps）。软封不重编码，此选项不生效
- **MP4 自动 `+faststart`**：moov 索引前置，HTTP 直链可边下边播、拖动不卡，媒体服务器无需先 remux（MKV 无此机制，按容器自动判断）
- **字幕时间偏移**：软封与硬压均支持整体平移字幕时间轴
- **输出格式**：MP4 / MKV
- **快捷方案**：软封推荐、4K 高质量、1080p 标准、快速出片、独显高效（H.265·NVENC）、核显专用（Intel QSV）一键切换
- **高级选项**：10-bit、HDR 透传、音频码率、音轨选择/延迟、音量标准化、自定义 FFmpeg 参数
- **批量处理**：按文件名自动配对视频与字幕，支持多字幕轨模式
- **文件名分析（AI）**：批量解析视频/字幕文件名，识别集数、推导配对关系并给出规范输出名建议。缺真实后缀的大文件会先用 ffprobe 补后缀（只补后缀、不改原名），只探测确含视频流的文件，隐藏文件与下载未完成的临时文件不参与
- **中英双语样式**：检测到中英双语字幕时自动转为带样式的 ASS（中文常规、英文小号灰色），硬压与软封共用
- **压缩效果预览**：多点采样（25% / 50% / 75%）试压缩，预估输出大小并截图对比
- **厂标（片头片尾识别符）**：勾选「厂标」后，内置厂标成片作为**独立片段接在正片之前/之后**，完全不遮挡画面（院线厂标 / 流媒体片头的做法；英文 ident / studio bumper）
  - **字幕时间轴不受影响**：字幕先烧进画面帧，再补黑场与叠厂标，补场只是把整段后移
  - **章节自动偏移**：源章节整体后移片头时长，跳章不会落到片头黑场
  - **时长自适应**：片段内置于程序，每次由 ffprobe 实测时长，换片源无需改配置
  - **片段自带音轨**：片头从 0 秒起播、片尾接在正片之后，叠在补出的静音上，正片音量不受影响；「全部音轨」时只叠在主轨，片源无音轨则只补黑场
  - **音频重编码**：补静音需走滤镜，无损片源在 MKV 下转 FLAC（采样逐个无损，仅丢 Atmos/DTS:X 对象元数据），其余转 AAC
  - **图形字幕（PGS/SUP）同样支持**，多段合并同样支持；软封不重编码画面，回退为文字标注

### 水印

独立于封装主流程的水印硬压任务（品牌取 `keys.json` 的 `watermark*` 字段）。每个源视频输出一个子目录，含硬压成品、5×3 封面拼图与 15 张预览截图。

- **随机化水印**：四角轮换 + 中央闪现两层，字号/透明度/阴影方向逐实例抖动，破坏 AI 模板匹配与固定裁剪
- **HDR 自动色调映射**：检测到 PQ / HLG 片源时自动插入 HDR→SDR 映射（该通路输出 8-bit，不映射会发灰发暗）
- **同时产出在线版**（可选）：与封装硬压共用规格与编码参数，同一条命令输出母版 + 同目录的 `<片名>.在线版.mp4`
- **成品汇总**：清理目录名与文件名里的特殊符号、防和谐填充字母，删掉 `.error.log` 等日志与中止残留的空目录，再按主播归类分成最多 10 个包，整体放进一个日期目录，可直接上传网盘
  - **日期目录**：`月日 + 3 位成品数量`（不足补零），如 09/21 汇总 194 个成品 → `E:\output\0921194\`，内含 `1_主播名\` … `10_主播名\`；统计口径是本次打包的非空成品目录数
  - **增量批次**：只打包当前还在输出目录顶层的成品，已有日期目录原样保留，方便「打包 → 上传 → 继续处理新片 → 再打包」；没有新成品时只做清理
  - **顺带清理**：顶层散落的日志、成品目录内的日志、上次中断残留的临时产物都会删掉；但对应成品已不存在时保留并给出警告
  - **防和谐填充字母**（`你n的d女n友y已y上s线x` → `你的女友已上线`）：只删夹在中文之间的孤立单个字母，成串英文词（`Yuki`、`Miss`）与紧挨数字/下划线的单个字母保留
  - **空目录**：中止任务残留的空壳（含只剩空 `screenshots`、只剩日志的）递归删除且不计入数量，隐藏文件保持原名不动

### 工具

- **视频信息查看** — 分辨率、编码、时长、音轨/字幕轨列表
- **字幕格式转换** — ASS ↔ SRT 互转（单文件/批量整目录）
- **字幕质量检查** — 空行、过短时长、时间重叠、过长文本检测
- **双语字幕合并** — 两个字幕文件按时间轴对齐合并，支持 SRT/ASS 输出
- **字幕自动翻译** — 内置 DeepSeek / GLM，另可接入 DeepL / 百度翻译 / 腾讯翻译君 API，一键翻译或生成双语；译文按字幕行业标准控长（英文 42 字符、中文 35 字），英文侧按母语口语用法重写
- **字幕自动同步** — 基于 ffsubsync 自动对齐字幕与视频音频
- **语音转字幕** — 两种引擎可选：
  - **千问云端 ASR**（阿里 DashScope）：本地提取音频后临时上传 OSS（识别完成即删除云端文件），返回字级时间戳并自动断句
  - **WhisperX 本地 ASR**（`large-v3` + GPU）：全程离线，自带 VAD 与多语种 wav2vec2 对齐模型
  - 两种引擎转写后都经规整流水线（折叠重复、清理片头/片尾幻觉、合并碎句、按阅读速度规整时长），再由内置 AI 做语义修正、外语译中，生成 **中英双语 SRT**（中文在上、英文在下）
  - 未配置 AI Key 时跳过语义修正与翻译，但仍输出经规整的字幕
  - 产物文件名带 `.AI修正`，已是双语成品
- **AI 字幕修复** — 对已有字幕纠错、去广告，输出 **中英双语**，按字幕原有形态分档处理：
  - **单中文字幕** → 润色简体中文 + 新译英文（繁体一并转简体）
  - **单英文字幕** → 校对英文 + 新译中文
  - **已成型的双语字幕** → 中文润色，英文只做保守校对（仅修同音误听、相邻重复虚词、半句重启；措辞、标点、大小写、口语词不动）
  - **日/韩/俄等第三语言** → 先译中文，再由中文译英文，保证中英同源对齐
  - 行内 `<i>`/`{\i1}` 等样式标签原样保留；批次失败自动重试与拆分，最差回退原文不丢行
- **文件名智能配对** — AI 按集数/相似度匹配视频与字幕并规范化重命名
- **视频片段裁剪** — 按起止时间裁剪，支持无损或重编码
- **多段视频合并** — 拖拽排序，无损合并或转码合并
- **视频缩略图网格** — 均匀取帧生成网格预览图
- **视频章节标记编辑** — 读取/添加/导入/写入章节标记
- **音频提取** — AAC / FLAC / MP3
- **视频截图** — 指定时间码导出 JPG
- **视频元数据编辑** — 写入 title / date / comment
- **VMAF / 视频质量评分** — VMAF、PSNR、SSIM 量化画质对比
- **FFmpeg 环境检测** — 显示版本、显卡、可用编码器，并附能力自检报告：逐项检查依赖的滤镜与选项（libass / libfreetype / 系统字体 / `-filter_script` / libzimg / `tpad` / 去重链路 / libvmaf / faststart / `-fps_mode` / NVENC 各编码器的 `-tune` 档位），每项标明缺失影响。启动时也会静默检测一遍，仅在存在致命缺失时提醒

### 字幕编辑

- 加载 SRT / ASS 字幕，表格形式编辑时间与文本
- 搜索/替换、添加/删除行
- **ASS 样式可视化编辑** — 字体、颜色拾色器、描边、阴影、对齐，实时预览

### 任务队列

- 多任务入队依次自动执行
- 支持定时开始（如凌晨 2:00）
- 完成后可执行关机/休眠
- **队列持久化**：排程写入程序目录的 `queue.json`，崩溃/断电/重启后自动恢复，无人值守跑长批次不会丢掉整份排程
  - 异常退出时正在执行的任务会标为失败并说明原因（产物可能不完整），确认后可点「重置失败」重新执行
  - 定时时间与「完成后操作」不持久化，重启后需重填

### 设置

- 翻译 API Key 管理（DeepSeek 内置/界面可填，可选 DeepL / 百度 / 腾讯）
- 千问 ASR 凭证（DashScope + OSS）可在「语音转字幕」页直接填写
- 水印文字/品牌/营销语可在「水印」页直接填写
- WhisperX 的 `python.exe` 路径、HTTP 代理、**模型目录**（浏览挂载）与一键检测
- ffsubsync 安装引导与一键检测
- 安装命令一键复制

### 历史

- 记录每次封装任务：文件名、模式、耗时、成功/失败，最多 100 条

### 可选依赖（按需安装）

| 功能 | 依赖 | 安装命令 / 说明 |
|------|------|----------|
| 字幕自动同步 | ffsubsync | `pip install ffsubsync` |
| VMAF 评分 | libvmaf | 需 FFmpeg 编译时包含 `--enable-libvmaf` |

> - WhisperX 为**本地**引擎，需自备 GPU 与 conda 环境；模型缓存目录优先级：**设置页「模型目录」> `keys.json` 的 `modelDir` > `E:\MuxerModels` > 系统默认缓存**，可挂载预先下载好的模型目录（清单见网盘内的 `模型说明.md`）。
> - 各引擎提取给模型的临时音频统一写入**输入视频所在目录**，处理完即删，不占 C 盘 Temp。

## 配置文件 `keys.json`

所有第三方密钥与可选品牌信息集中放在程序目录（`Muxer.exe` 同目录）的 `keys.json`，模板见 `keys.example.json`。查找顺序：`Muxer.exe` 同目录 → 当前工作目录 → `%APPDATA%\Muxer\keys.json`；保存时写回已存在的那个文件，写入前自动留一份 `keys.json.bak`：

| 字段 | 说明 |
|------|------|
| `aiProvider` | 当前启用的 AI 提供商，取值 `deepseek` 或 `zhipu`（GLM，`glm` 视为同义） |
| `deepseekKey` | DeepSeek API Key（翻译 / AI 修复 / ASR 后校对 / 文件名解析） |
| `zhipuKey` | 智谱 GLM API Key（与 `aiProvider` 配合使用） |
| `dashscopeKey` | 阿里云 DashScope（千问 ASR） |
| `ossAccessKeyID` / `ossAccessKeySecret` | 阿里云 OSS（千问 ASR 上传音频用） |
| `ossBucket` / `ossEndpoint` | OSS 存储桶名 / 区域端点，留空走默认 `muxer-asr` / `oss-cn-shanghai.aliyuncs.com` |
| `modelDir` | WhisperX 模型目录默认值（设置页未填时的兜底） |
| `brandName` / `brandUrl` / `brandTag` | **封装/合并主流程**的站点品牌：站点名 / 域名 / 输出文件名标签 |
| `watermarkUrl` / `watermarkBrand` / `watermarkTagline` | **独立水印任务**的网址 / 品牌名 / 营销语，留空则不打水印、不写品牌元数据 |

> **两套品牌互不相干**：`brand*` 用于封装/合并（元数据、屏上水印、厂标、输出文件名标签、字幕清理、AI 提示词身份）；`watermark*` 只服务于「水印」标签页的独立任务。二者可以指向完全不同的站点。
>
> `brand*` 取值顺序：
> 1. 显式填了 → 用填的值；
> 2. 未填但 `keys.json` 存在 → 使用默认品牌 `低端影视 / ddys.io / DDYS`；
> 3. 没有 `keys.json` → 全部不打品牌：不写元数据、不打屏上水印、不生成厂标、输出文件名用中性后缀 `.merged`。
>
> **「已配置即隐藏」**：`keys.json` 里已配置的项，界面不再显示对应输入框，直接使用配置文件；未配置时才显示输入框让使用者自填。涉及 DeepSeek Key、「水印」页的水印信息、千问 ASR 凭证三处。优先级统一为 **`keys.json` > 界面填写**；DeepL / 百度 / 腾讯翻译 Key 不在 `keys.json`，始终在界面填写。
>
> **分享给他人时只需删除 `keys.json`**：程序内不含任何密钥，对方在界面填自己的即可，模型目录与水印品牌也随之留空。
>
> **编码要求 UTF-8**：用记事本编辑后若选「ANSI」保存，程序会尝试按 GBK 兼容读取并在日志给出提示；JSON 语法有误（缺逗号、中文引号等）时启动会告警并按「未配置」运行。写入采用「临时文件 + 原子替换」，主文件损坏且存在 `.bak` 时会自动从备份恢复。

### 分发安全

`keys.json` 是**明文**存储的，里面是真实的 DeepSeek / DashScope / OSS 密钥。

| 分发方式 | 是否泄露密钥 | 说明 |
|---|---|---|
| `Muxer-amd64-installer.exe` 安装包 | **否** | NSIS 只打包 `Muxer.exe` 与 WebView2 引导器 |
| 单独发 `Muxer.exe` | **否** | 程序本身不含任何密钥 |
| **整个 `build\bin` 文件夹** | **是** | 该目录下就放着 `keys.json`，会一并送出 |

- 分享时执行 **`打包分享版.bat`**：它会重新构建，并在 `build\share\` 生成只含 `Muxer.exe`、安装包和 `keys.example.json` 的干净目录，同时校验该目录内确实不存在 `keys.json`（存在则中止）。
- 建议把 `keys.json` 单独备份到项目之外的私密位置：它只有这一份，清理 `build` 目录会连带删除。
- 本仓库只提交源码与 `keys.example.json`，`build\bin`、`build\share` 与本地配置不入库。

## 构建与运行

### 前置：安装 Wails CLI

若 `wails` 命令不可用，需先安装：

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

安装后确保 `%USERPROFILE%\go\bin` 已加入系统 PATH。国内网络可设置代理后安装：

```powershell
$env:HTTP_PROXY="http://127.0.0.1:7890"; $env:HTTPS_PROXY=$env:HTTP_PROXY; go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

端口取决于代理软件，把 `7890` 换成实际监听的端口即可：

| 代理软件 | 默认端口 |
|------|------|
| Clash / Clash for Windows / Mihomo | `7890` |
| Clash Verge Rev | `7897` |
| v2rayN | HTTP `10809`（SOCKS `10808`） |
| sing-box / Hiddify | `2080` |
| Netch | `2801` |
| Shadowsocks-windows | SOCKS `1080` |

端口在软件主界面或设置里能看到；系统代理开启时也可以直接读出来：`(Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings').ProxyServer`。少见的自定义端口同样按这个办法查。

Go 只认 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量（以及 `NO_PROXY`），Windows 的系统代理设置对它无效，所以必须显式设一次；这个变量只在当前 PowerShell 会话里有效。

### 编译命令

最简单的方式是直接双击运行项目根目录的 **`编译.bat`**：它会注入构建日期、编译 `Muxer.exe` 并顺带打出 NSIS 安装包。手动等价命令：

```bash
# 开发模式（热重载）
wails dev

# 生产构建：GUI 子系统 + 注入构建日期 + 同时生成安装包
wails build -ldflags "-H windowsgui -X main.BuildTime=2026-11-01" -nsis
```

**参数说明：**
- `-ldflags "-H windowsgui"`：编译为纯 GUI 应用，启动时不分配控制台
- `-X main.BuildTime=...`：注入「关于」页显示的构建日期
- `-nsis`：同时生成 `build/bin/Muxer-amd64-installer.exe`

构建完成后可执行文件位于 `build/bin/Muxer.exe`。

### 冒烟测试

`scripts\smoke.ps1` 在系统临时目录里自建素材（30s 测试视频 + SRT），逐项验证 ffmpeg/ffprobe 可用性、`go vet`、硬压烧录、时间轴起点、混合输入合并与分享包不含密钥，跑完自动清理临时目录。失败项会打印原因并以退出码 `1` 结束，可直接用于打包前的自检。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\smoke.ps1
```

需要 `ffmpeg`、`ffprobe`、`go` 在 PATH 中。

## 注意事项

- MP4 + ASS 软封会转为 mov_text，ASS 特效丢失，建议用 MKV
- 硬压会跳过文件名含硬压关键词（HC、HARDSUB）的视频
- 多字幕轨建议用 MKV，MP4 支持有限
- 编码器可用性以「设置 → FFmpeg 环境检测」为准
- **输出文件名标识按实际封装进去的字幕内容自动生成**（模板留空时生效，手填模板永远优先）：
  - 一条中英叠显轨 → `中英字幕`；简体 + 英文两条独立轨 → `简英双字幕`；简繁英三轨 → `简繁英`；仅简体 / 仅繁体 → `简中` / `繁中`；仅英文 → `英字`；无可判定字幕 → 不加标识
  - `中英字幕`（一条轨中英文叠显）与 `中英双字幕`（两条独立可切换的轨）含义不同，混用会给出错误信息
  - 简繁自动判定，判不出时退回「中」，不做猜测
- 封装流程会**只保留一条中文文本字幕**，非中文与多余的中文轨会被丢弃（日志有 warn 级清单）。同时给中文和英文两个字幕文件时，英文那条不会进成品
- 封装/硬压**失败或中途取消时会自动删除未完成的半成品输出**（错误日志 `.error.log` 仍单独保留供排查）
- **容器索引自动修复**：收尾阶段异常退出可能把画面写完却没写索引（`Cues`/`Duration`），此时播放器与网盘拖动会卡住。程序会自动 `-c copy` 重封装一次补回索引 —— **只换容器、不重新编码**，硬压烧进画面的字幕一个像素都不变，MP4 成品会保住 `+faststart`；修不好则保留源文件供复查
- **在线版（`.在线版.mp4`）同样校验可读时长**：母版与在线版由同一条命令产出，收尾异常时在线版可能缺 `moov` 无法播放。这种文件体积看着正常，所以在线版额外要求能读到时长；不合格就保留源片
- 字幕文件名可以带 `[zmk.pw]`、逗号、空格等符号，无需手动改写
- 内封字幕提取会**优先取文本轨**（跳过 PGS/VobSub 图形轨），仅在整片只有图形字幕时才提取图形轨
- WhisperX 为本地引擎，需在「设置」配置 conda 环境 `python.exe` 与**模型目录**；模型目录默认 `E:\MuxerModels`，也可在设置页挂载预先下载好的模型（清单见网盘内的 `模型说明.md`）
