# Muxer — 影片字幕封裝工具

[简体中文](README.md) · **繁體中文** · [English](README.en.md)

**Muxer** 是一套以 [Wails v2](https://wails.io/) 打造的 Windows 桌面程式，用來把外掛字幕與影片封裝在一起（軟封或硬壓），並內建一整套影片與字幕處理工具。介面為中文，針對影視字幕組、個人收藏整理等本機批次處理的需求設計。

所有媒體處理都交由本機的 **FFmpeg** 執行，影片不會上傳到任何伺服器；只有語音轉字幕、AI 字幕校對這類功能會呼叫你自己設定的雲端 API。

專案：<https://github.com/MuxerGUI/Muxer> · 授權：[MIT](LICENSE)

## 功能特色

### 封裝（核心）

- **軟封（內嵌字幕軌）**：視訊流直接複製，字幕寫成獨立軌道，畫質零損失
- **硬壓（燒進畫面）**：H.264 / H.265 / AV1，支援 CPU 與 GPU（NVENC / AMF / QSV）。硬體編碼不可用時自動改用 CPU 重試一次
- **關鍵影格間隔上限**：硬壓輸出依影格率設定約 2 秒的關鍵影格間隔，確保拖曳定位準確、HLS 切段能對齊
- **同時產出線上版**（硬壓選用）：同一道 FFmpeg 指令同時輸出母檔與一份 1080p 輕量 MP4，共用一次解碼與一次字幕燒錄。線上版與母檔放在同一目錄、同主檔名加 `.在线版.mp4` 後綴，立體聲 AAC、`+faststart`、約 2 秒關鍵影格；位元率留空時跟隨來源（上限 3000 kbps）。軟封不重新編碼，此選項不生效
- **MP4 自動 `+faststart`**：moov 索引搬到檔案開頭，HTTP 直連可邊下邊播、拖曳不卡，媒體伺服器也不必先 remux（MKV 沒有這項機制，程式會依容器自動判斷）
- **字幕時間位移**：軟封與硬壓都支援整條字幕時間軸平移
- **輸出格式**：MP4 / MKV
- **快速方案**：軟封推薦、4K 高畫質、1080p 標準、快速出片、獨顯高效（H.265·NVENC）、內顯專用（Intel QSV）一鍵切換
- **進階選項**：10-bit、HDR 直通、音訊位元率、音軌選擇／延遲、音量正規化、自訂 FFmpeg 參數
- **批次處理**：依檔名自動配對影片與字幕，支援多字幕軌模式
- **檔名分析（AI）**：批次解析影片／字幕檔名，辨識集數、推算配對關係並給出規範的輸出檔名建議。缺少真實副檔名的大檔會先用 ffprobe 補上副檔名（只補副檔名、不改原名），只探測確實含視訊流的檔案，隱藏檔與下載未完成的暫存檔不列入處理
- **中英雙語樣式**：偵測到中英雙語字幕時自動轉為帶樣式的 ASS（中文正常大小、英文小號灰色），硬壓與軟封共用
- **壓縮效果預覽**：多點取樣（25% / 50% / 75%）試壓縮，預估輸出大小並附截圖對照
- **片頭片尾識別標**：勾選後，內建的識別成片會當成**獨立片段接在正片前後**，完全不會遮到畫面（院線片頭／串流平台的做法，英文 ident / studio bumper）
  - **字幕時間軸不受影響**：字幕先燒進畫面影格，再補黑場與疊上識別標，補場只是把整段往後推
  - **章節自動位移**：來源章節整體後移片頭長度，跳章不會跳到片頭黑場
  - **長度自動偵測**：片段內建於程式中，每次由 ffprobe 實測長度，換片源不必改設定
  - **片段自帶音軌**：片頭從 0 秒開始播、片尾接在正片之後，疊在補出來的靜音上，正片音量不受影響；選「全部音軌」時只疊在主軌，來源沒有音軌就只補黑場
  - **音訊重新編碼**：補靜音得走濾鏡，無損來源在 MKV 下轉 FLAC（取樣逐一無損，只失去 Atmos/DTS:X 物件資訊），其餘轉 AAC
  - **圖形字幕（PGS/SUP）同樣支援**，多段合併同樣支援；軟封不重新編碼畫面，會退回文字標註

### 浮水印

獨立於封裝主流程的浮水印硬壓工作（品牌取自 `keys.json` 的 `watermark*` 欄位）。每支來源影片輸出一個子目錄，內含硬壓成品、5×3 封面拼圖與 15 張預覽截圖。

- **隨機化浮水印**：四角輪替 + 中央快閃兩層，字級／透明度／陰影方向逐次抖動，讓 AI 範本比對與固定裁切失效
- **HDR 自動色調對映**：偵測到 PQ / HLG 來源時自動插入 HDR→SDR 對映（此流程輸出 8-bit，不對映會灰掉變暗）
- **同時產出線上版**（選用）：與封裝硬壓共用規格與編碼參數，同一道指令輸出母檔與同目錄的 `<片名>.在线版.mp4`
- **成品彙整**：清掉目錄名與檔名裡的特殊符號、防和諧填充字母，刪除 `.error.log` 等日誌與中止殘留的空目錄，再依主播歸類分成最多 10 個包，整批放進一個日期目錄，可直接上傳網路硬碟
  - **日期目錄**：`月日 + 3 位成品數量`（不足補零），例如 09/21 彙整 194 個成品 → `E:\output\0921194\`，裡面是 `1_主播名\` … `10_主播名\`；計算基準是這批實際有內容的成品目錄數
  - **增量批次**：只打包目前還在輸出目錄最上層的成品，既有的日期目錄原樣保留，方便「打包 → 上傳 → 繼續處理新片 → 再打包」；沒有新成品時只做清理
  - **順手清理**：散落在最上層的日誌、成品目錄內的日誌、上次中斷殘留的暫存產物都會一併刪除；但對應成品已不存在時予以保留並提出警告
  - **防和諧填充字母**（`你n的d女n友y已y上s线x` → `你的女友已上线`）：只刪夾在中文之間的單一孤立字母，成串英文詞（`Yuki`、`Miss`）與緊鄰數字／底線的單一字母照舊保留
  - **空目錄**：中止工作殘留的空殼（包含只剩空 `screenshots`、只剩日誌的）會遞迴刪除且不列入數量，隱藏檔維持原名不動

### 工具

- **影片資訊檢視** — 解析度、編碼、長度、音軌／字幕軌清單
- **字幕格式轉換** — ASS ↔ SRT 互轉（單檔／整個目錄批次）
- **字幕品質檢查** — 空行、時間過短、時間重疊、文字過長偵測
- **雙語字幕合併** — 兩份字幕依時間軸對齊合併，支援 SRT/ASS 輸出
- **字幕自動翻譯** — 內建 DeepSeek / GLM，另可接入 DeepL / 百度翻譯 / 騰訊翻譯君 API，一鍵翻譯或產生雙語；譯文依字幕業界標準控制長度（英文 42 字元、中文 35 字），英文端依母語口語習慣改寫
- **字幕自動同步** — 以 ffsubsync 自動對齊字幕與影片音訊
- **語音轉字幕** — 兩種引擎可選：
  - **千問雲端 ASR**（阿里 DashScope）：本機抽出音訊後暫存上傳 OSS（辨識完成即刪除雲端檔案），回傳字級時間戳並自動斷句
  - **WhisperX 本機 ASR**（`large-v3` + GPU）：全程離線，自帶 VAD 與多語系 wav2vec2 對齊模型
  - 兩種引擎轉寫後都經過整理流程（折疊重複、清掉片頭／片尾幻聽、合併碎句、依閱讀速度調整長度），再由內建 AI 做語意修正、外語譯中，產出**中英雙語 SRT**（中文在上、英文在下）
  - 未設定 AI Key 時跳過語意修正與翻譯，但仍輸出整理過的字幕
  - 產出檔名帶 `.AI修正`，已經是雙語成品
- **AI 字幕校對** — 針對現有字幕糾錯、去廣告，輸出**中英雙語**，依字幕原本的形態分級處理：
  - **純中文字幕** → 潤飾簡體中文 + 新譯英文（繁體一併轉簡體）
  - **純英文字幕** → 校對英文 + 新譯中文
  - **已成形的雙語字幕** → 中文潤飾，英文只做保守校對（僅修同音誤聽、相鄰重複虛詞、半句重啟；措辭、標點、大小寫、口語詞一律不動）
  - **日／韓／俄等第三語言** → 先譯中文，再由中文譯英文，確保中英同源對齊
  - 行內 `<i>`/`{\i1}` 等樣式標籤原樣保留；批次失敗自動重試與拆分，最差退回原文，不會掉行
- **檔名智慧配對** — AI 依集數／相似度比對影片與字幕，並規範化重新命名
- **影片片段剪裁** — 依起訖時間剪裁，支援無損或重新編碼
- **多段影片合併** — 拖曳排序，無損合併或轉檔合併
- **影片縮圖拼版** — 均勻取影格產生拼版預覽圖
- **章節標記編輯** — 讀取／新增／匯入／寫入章節標記
- **音訊擷取** — AAC / FLAC / MP3
- **影片截圖** — 指定時間碼匯出 JPG
- **影片中繼資料編輯** — 寫入 title / date / comment
- **VMAF / 影片品質評分** — VMAF、PSNR、SSIM 量化畫質比較
- **FFmpeg 環境檢測** — 顯示版本、顯示卡、可用編碼器，並附能力自檢報告：逐項檢查相依的濾鏡與選項（libass / libfreetype / 系統字型 / `-filter_script` / libzimg / `tpad` / 去重流程 / libvmaf / faststart / `-fps_mode` / NVENC 各編碼器的 `-tune` 檔位），每項標明缺少時的影響。啟動時也會靜默檢查一次，只在有致命缺失時提醒

### 字幕編輯

- 載入 SRT / ASS 字幕，以表格編輯時間與文字
- 搜尋／取代、新增／刪除列
- **ASS 樣式視覺化編輯** — 字型、顏色取色器、描邊、陰影、對齊，即時預覽

### 工作佇列

- 多項工作排入佇列依序自動執行
- 支援排定時間開始（例如凌晨 2:00）
- 完成後可執行關機／休眠
- **佇列保存**：排程寫入程式目錄的 `queue.json`，當機／斷電／重啟後自動還原，無人顧機跑長批次也不會丟掉整份排程
  - 異常結束時正在執行的工作會被標為失敗並說明原因（產物可能不完整），確認後可按「重設失敗」重新執行
  - 排定時間與「完成後動作」不會保存，重啟後需重新填寫

### 設定

- 翻譯 API Key 管理（DeepSeek 內建／介面可填，另可選 DeepL / 百度 / 騰訊）
- 千問 ASR 憑證（DashScope + OSS）可直接在「語音轉字幕」頁填寫
- 浮水印文字／品牌／標語可直接在「浮水印」頁填寫
- WhisperX 的 `python.exe` 路徑、HTTP 代理、**模型目錄**（瀏覽掛載）與一鍵檢測
- ffsubsync 安裝引導與一鍵檢測
- 安裝指令一鍵複製

## 環境需求

- **Go** 1.23+
- **Node.js**（前端 `npm install` / `npm run build`）
- **FFmpeg**（含 ffprobe）已安裝並加入 **PATH**
- 目前為 **Windows** 設定

### 選用相依（依需求安裝）

| 功能 | 相依 | 安裝指令 / 說明 |
|------|------|----------|
| 字幕自動同步 | ffsubsync | `pip install ffsubsync` |
| VMAF 評分 | libvmaf | 需 FFmpeg 編譯時包含 `--enable-libvmaf` |
| WhisperX 本機 ASR | Python + CUDA + WhisperX | 獨立的 conda 環境（含 PyTorch CUDA、`whisperx`、`faster-whisper`），在「設定」中填入該環境的 `python.exe` 路徑 |

> - 語音轉字幕（千問 ASR）與 AI 字幕處理（DeepSeek / GLM，依 `aiProvider` 切換）走雲端 API，需要 DeepSeek 或 GLM / DashScope（千問）/ 阿里雲 OSS 的 Key。金鑰統一從程式目錄的 `keys.json` 讀取（見下方「設定檔 keys.json」），未設定時相關功能會提示填寫。
> - DeepSeek 的取樣溫度範圍是 `0~2`，GLM 是 `0~1`，程式內部已依廠商換算，不必手動調整。GLM 的思考模式固定開啟，無法關閉。
> - WhisperX 是**本機**引擎，需自備 GPU 與 conda 環境；模型快取目錄優先順序：**設定頁「模型目錄」> `keys.json` 的 `modelDir` > `E:\MuxerModels` > 系統預設快取**，可掛載事先下載好的模型目錄（清單見網路硬碟內的 `模型說明.md`）。
> - 各引擎抽給模型的暫存音訊統一寫在**來源影片所在目錄**，處理完立即刪除，不佔 C 槽 Temp。

## 設定檔 `keys.json`

所有第三方金鑰與選用的品牌資訊集中在程式目錄（與 `Muxer.exe` 同層）的 `keys.json`，範本見 `keys.example.json`。尋找順序：`Muxer.exe` 同目錄 → 目前工作目錄 → `%APPDATA%\Muxer\keys.json`；儲存時寫回已存在的那一個，寫入前自動留一份 `keys.json.bak`：

| 欄位 | 說明 |
|------|------|
| `aiProvider` | 目前啟用的 AI 供應商，值為 `deepseek` 或 `zhipu`（GLM，`glm` 視為同義） |
| `deepseekKey` | DeepSeek API Key（翻譯 / AI 校對 / ASR 後校對 / 檔名解析） |
| `zhipuKey` | 智譜 GLM API Key（與 `aiProvider` 搭配使用） |
| `dashscopeKey` | 阿里雲 DashScope（千問 ASR） |
| `ossAccessKeyID` / `ossAccessKeySecret` | 阿里雲 OSS（千問 ASR 上傳音訊用） |
| `ossBucket` / `ossEndpoint` | OSS 儲存桶名稱 / 區域端點，留空則用預設 `muxer-asr` / `oss-cn-shanghai.aliyuncs.com` |
| `modelDir` | WhisperX 模型目錄預設值（設定頁未填時的備援） |
| `brandName` / `brandUrl` / `brandTag` | **封裝／合併主流程**的站點品牌：站名 / 網域 / 輸出檔名標籤 |
| `watermarkUrl` / `watermarkBrand` / `watermarkTagline` | **獨立浮水印工作**的網址 / 品牌名 / 標語，留空則不加浮水印、不寫品牌中繼資料 |

> **兩套品牌互不相干**：`brand*` 用於封裝／合併（中繼資料、畫面浮水印、識別標、輸出檔名標籤、字幕清理、AI 提示詞身分）；`watermark*` 只服務「浮水印」分頁的獨立工作。兩者可以指向完全不同的站點。
>
> `brand*` 取值順序：
> 1. 有明確填寫 → 用填的值；
> 2. 沒填但 `keys.json` 存在 → 使用預設品牌 `低端影视 / ddys.io / DDYS`；
> 3. 沒有 `keys.json` → 全部不加品牌：不寫中繼資料、不加畫面浮水印、不產生識別標、輸出檔名改用中性後綴 `.merged`。
>
> **「已設定即隱藏」**：`keys.json` 裡已設定的項目，介面不再顯示對應輸入框，直接採用設定檔；未設定時才顯示輸入框讓使用者自行填寫。涉及 DeepSeek Key、「浮水印」頁的浮水印資訊、千問 ASR 憑證三處。優先順序統一為 **`keys.json` > 介面填寫**；DeepL / 百度 / 騰訊翻譯 Key 不在 `keys.json`，一律在介面填寫。
>
> **要分享給別人時只要刪掉 `keys.json`**：程式本身不含任何金鑰，對方在介面填自己的即可，模型目錄與浮水印品牌也隨之留空。
>
> **編碼要求 UTF-8**：用記事本編輯後若選「ANSI」儲存，程式會嘗試以 GBK 相容方式讀取並在日誌提示；JSON 語法有誤（漏逗號、中文引號等）時啟動會警告並以「未設定」狀態執行。寫入採「暫存檔 + 原子替換」，主檔損毀且存在 `.bak` 時會自動從備份還原。

### 散布安全

`keys.json` 是**明文**儲存的，裡面是真實的 DeepSeek / DashScope / OSS 金鑰。

| 散布方式 | 是否洩漏金鑰 | 說明 |
|---|---|---|
| `Muxer-amd64-installer.exe` 安裝檔 | **否** | NSIS 只打包 `Muxer.exe` 與 WebView2 引導程式 |
| 單獨傳 `Muxer.exe` | **否** | 程式本身不含任何金鑰 |
| **整個 `build\bin` 資料夾** | **是** | 該目錄下就放著 `keys.json`，會一併送出 |

- 要分享時執行 **`打包分享版.bat`**：它會重新建置，並在 `build\share\` 產生只含 `Muxer.exe`、安裝檔與 `keys.example.json` 的乾淨目錄，同時檢查該目錄裡確實沒有 `keys.json`（有就直接中止）。
- 建議把 `keys.json` 另外備份到專案之外的私密位置：它只有這一份，清理 `build` 目錄會一併刪掉。
- 本專案只提交原始碼與 `keys.example.json`，`build\bin`、`build\share` 與本機設定不進版控。

## 建置與執行

### 前置：安裝 Wails CLI

若 `wails` 指令不可用，需先安裝：

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

安裝後確認 `%USERPROFILE%\go\bin` 已加入系統 PATH。中國大陸網路可先設代理再安裝：

```powershell
$env:HTTP_PROXY="http://127.0.0.1:7890"; $env:HTTPS_PROXY="http://127.0.0.1:7890"; go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

### 建置指令

最省事的方式是直接雙擊專案根目錄的 **`编译.bat`**：它會注入建置日期、編譯 `Muxer.exe`，並順帶產出 NSIS 安裝檔。等效的手動指令：

```bash
# 開發模式（熱重載）
wails dev

# 正式建置：GUI 子系統 + 注入建置日期 + 同時產出安裝檔
wails build -ldflags "-H windowsgui -X main.BuildTime=2026-11-01" -nsis
```

**參數說明：**
- `-ldflags "-H windowsgui"`：編譯為純 GUI 程式，啟動時不開主控台視窗
- `-X main.BuildTime=...`：注入「關於」頁顯示的建置日期
- `-nsis`：同時產出 `build/bin/Muxer-amd64-installer.exe`

建置完成後執行檔位於 `build/bin/Muxer.exe`。

### 快速煙霧測試

`scripts\smoke.ps1` 會在系統暫存目錄自行產生素材（30 秒測試影片 + SRT），逐項驗證 ffmpeg/ffprobe 可用性、`go vet`、硬壓燒錄、時間軸起點、混合來源合併，以及分享包不含金鑰，跑完自動清除暫存目錄。失敗項目會印出原因並以離開碼 `1` 結束，可直接當作打包前的自檢。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\smoke.ps1
```

需要 `ffmpeg`、`ffprobe`、`go` 都在 PATH 中。

## 注意事項

- MP4 搭配 ASS 軟封會轉成 mov_text，ASS 特效會遺失，建議用 MKV
- 硬壓會跳過檔名含硬壓關鍵字（HC、HARDSUB）的影片
- 多字幕軌建議用 MKV，MP4 支援有限
- 編碼器可用性以「設定 → FFmpeg 環境檢測」為準
- **輸出檔名標籤依實際封裝進去的字幕內容自動產生**（範本留空時生效，手填範本永遠優先）：
  - 一條中英疊顯軌 → `中英字幕`；簡體 + 英文兩條獨立軌 → `簡英双字幕`；簡繁英三軌 → `简繁英`；僅簡體 / 僅繁體 → `简中` / `繁中`；僅英文 → `英字`；無法判定 → 不加標籤
  - `中英字幕`（單軌中英疊顯）與 `中英双字幕`（兩條可切換的獨立軌）意思不同，混用會給出錯誤訊息
  - 簡繁自動判定，判定不出時退回「中」，不做猜測
- 封裝流程會**只保留一條中文文字字幕**，非中文與多餘的中文軌會被丟棄（日誌有 warn 等級清單）。同時給中文與英文兩份字幕檔時，英文那一份不會進成品
- 封裝／硬壓**失敗或中途取消時會自動刪除未完成的半成品**（錯誤日誌 `.error.log` 仍會單獨保留供追查）
- **容器索引自動修復**：收尾階段異常結束可能把畫面寫完卻沒寫索引（`Cues`/`Duration`），這時播放器與網路硬碟拖曳會卡住。程式會自動 `-c copy` 重新封裝一次補回索引 —— **只換容器、不重新編碼**，硬壓燒進畫面的字幕一個像素都不會變，MP4 成品會保住 `+faststart`；修不好則保留來源檔案供複查
- **線上版（`.在线版.mp4`）同樣會驗證能否讀到長度**：母檔與線上版由同一道指令產出，收尾異常時線上版可能缺少 `moov` 而完全無法播放。這種檔案大小看起來正常，所以線上版額外要求能讀到長度；不合格就保留來源
- 字幕檔名可以帶 `[zmk.pw]`、逗號、空格等符號，不需要手動改名
- 內封字幕擷取會**優先取文字軌**（跳過 PGS/VobSub 圖形軌），只有整片僅有圖形字幕時才擷取圖形軌
- WhisperX 是本機引擎，需在「設定」設定 conda 環境 `python.exe` 與**模型目錄**；模型目錄預設 `E:\MuxerModels`，也可在設定頁掛載事先下載好的模型（清單見網路硬碟內的 `模型說明.md`）
